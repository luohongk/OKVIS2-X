# EGO 设备数据标注平台设计

## 目标与范围

在运行 OKVIS2-X 的工作站上提供一个局域网 Web 平台，自动索引 `/home/conanluo/okvis_data`，按设备和序列选择数据，选择 `/root/OKVIS2-X/config/myfisheye4` 下的 YAML 配置，一键提交一个或多个 VIO 任务，并查看实时日志、历史状态和 3D 位姿轨迹。

第一版不包含账号与权限分级、人工轨迹修订、外部数据库或移动端专项适配。

## 总体架构

采用 FastAPI、React/Vite 和 SQLite：

- FastAPI 提供数据索引、配置枚举、任务管理、SSE 日志和结果下载接口。
- React 构建多页面单页应用，生产构建由 FastAPI 统一托管。
- SQLite 持久化任务、任务组和运行参数；服务重启后保留历史。
- 后端复用 `mcap_vio_run/run_mcap_vio.py`，不复制抽取和 VIO 逻辑。
- 每个任务使用独立的设备、序列、配置和任务 ID 输出目录，避免同名序列冲突。

服务默认部署在 OKVIS 工作站并监听局域网地址。全局并发上限由环境变量配置，当前默认值为 8，但可根据内存压力降低。

## 数据和配置发现

后端只访问两个固定根目录：

- 数据：`/home/conanluo/okvis_data`
- 配置：`/root/OKVIS2-X/config/myfisheye4`

设备为数据根目录下的一级目录。只有包含有效 MCAP 序列的设备才显示。序列为设备目录下的二级目录，必须包含 `cam0`、`cam1`、`cam2`、`cam3` 和 `imu`。平台读取 `.complete` 和同名 `.info`，展示完整性、采集时长、平台名等信息。

配置接口递归列出配置根目录内的 `.yaml` 文件，以相对路径作为稳定标识。客户端不能提交任意绝对路径。后端在每次提交时重新解析并校验所有路径位于固定根目录内。

## 页面结构

### 数据运行

- 展示有效设备及其序列数量。
- 进入设备后展示可搜索、多选和全选的序列表格。
- 展示序列名、采集时长、设备元数据、完整性和历史运行状态。
- 通过可搜索下拉框选择 YAML 配置。
- 提供相机解码线程数、是否保留图片等白名单选项。
- 提交前展示设备、序列数、配置和并发占用摘要。
- 不暴露原始 `EXTRA_ARGS`。

### 任务中心

- 展示任务组、单序列任务及排队、抽取、VIO、成功、失败和中断状态。
- 支持按设备、序列、配置和状态过滤。
- 使用 SSE 展示实时阶段和日志增量。
- 刷新或重新连接后恢复任务视图。
- 失败任务展示退出码和最后错误片段，并可按原参数重试。

### 结果详情

- 使用 `okvis2-slam-calib-final_trajectory.csv` 的 `p_WS_W_x/y/z` 绘制 Plotly 3D 轨迹。
- 展示点数、起止时间、轨迹包围盒、总位移和运行参数。
- 列出原始 CSV、地图 CSV、G2O、日志和状态文件并支持单独下载。
- 仅在用户请求时生成批量下载包。
- 成功但缺少最终轨迹时明确显示产物不完整，不生成虚假图表。

页面采用深色石墨、示波器网格和青绿色状态色的工业实验台视觉。顶部保留全局并发状态，以及数据运行、任务中心和结果详情入口。主要适配工作站显示器和普通笔记本。

## 任务数据流

1. 前端提交设备名、序列名列表、配置相对路径和白名单选项。
2. 后端重新校验设备、序列、配置及传感器目录。
3. 后端创建一个任务组，并为每个序列创建独立任务记录。
4. 进程内调度器按全局信号量启动任务。
5. 子进程通过参数数组调用 `run_mcap_vio.py`，不经过 shell。
6. 每个任务显式传入独立中间目录和结果目录。
7. 后端从 `extract.log`、`okvis.log` 和 `status.txt` 推导任务阶段，并通过 SSE 推送增量事件。
8. 单个序列失败不阻断同组其他序列。
9. 服务启动时，将先前仍处于排队或运行状态的任务标记为中断，不自动重跑。

## 安全与错误处理

- 索引错误作为页面级阻断告警。
- 提交错误返回具体字段信息，不创建任务。
- 运行错误保留阶段、退出码、日志和输出目录。
- 所有路径在服务端从固定根目录和受控相对标识解析。
- 所有子进程使用参数数组启动，禁止 shell 拼接。
- 下载接口验证目标文件位于对应任务输出目录内。
- 原始数据集只读，所有中间数据和结果写入独立工作目录。
- 服务启动时检查 OKVIS 可执行文件、Python 依赖和根目录，只报告状态，不自动修改环境。

## 测试策略

- Python 单元测试：目录过滤、路径边界、配置枚举、状态转换和轨迹 CSV 解析。
- FastAPI 接口测试：使用临时目录构造有效与无效 MCAP 结构，以假进程替代真实 OKVIS。
- React 测试：多选、提交校验、任务状态、日志空状态和轨迹空状态。
- 手工端到端检查：用真实短序列验证数据发现、提交、实时日志、成功轨迹和下载。
- 默认自动化测试不启动真实 VIO 运算。

## 代码与部署

新增 `mcap_vio_web/`：

- `backend/`：FastAPI、数据库、索引、调度、结果解析和测试。
- `frontend/`：React/Vite 页面、API 客户端、SSE 与前端测试。
- 单一启动入口：生产模式托管构建后的前端资源。

数据根目录、配置根目录、仓库根目录、输出根目录和并发数通过环境变量覆盖。提供一键启动脚本；第一版不自动安装 systemd 服务。
